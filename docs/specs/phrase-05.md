# Phase 5 — 详情面板

目标： 点击地图上的任何元素，都能了解它是什么。

## 构建内容

- 未选中任何元素时面板显示的内容，这是用户首先看到的内容。展示整个仓库的摘要：仓库名称、检测到的框架，以及文件、导入关系和路由的数量。然后展示两个排序列表——仓库中其他部分最依赖的文件，按照被导入的次数排序；以及完全没有被导入的文件，这些文件是开始阅读代码的切入点。最后展示无法通过任何约定识别类型的文件数量。
- 右侧面板根据当前选中的元素填充内容：文件路径、文件类型、文件长度、它依赖多少个文件，以及有多少个文件依赖它，然后列出这两类依赖关系的完整列表。
- 面板中有两个标签页：Structure（结构） 和 Explanation（解释）。Structure 展示上述所有内容。Explanation 目前显示空状态——在通过模型调用生成内容之前，这里不会填充任何信息。
- 选中一个折叠的文件夹时，显示相同的两个标签页，其中 Structure 列出文件夹内部包含哪些类型的文件，以及每种类型的数量。
- 面板中显示的每个文件路径都可以点击，点击后地图的选中状态会切换到对应文件。
- 将鼠标悬停在面板中的相邻节点上时，地图上对应的节点会高亮。将鼠标悬停在地图上的节点时，面板中对应的节点也会高亮。两个方向都要支持。

## 约束

- 取消选中后返回仓库摘要。这是面板的默认状态，而不是占位内容。
- 选中任何元素都不会触发网络请求。面板所需的所有数据都已经存在于浏览器中。
- 切换选中元素时，当前打开的标签页保持不变。用户在比较三个文件的解释内容时，不应该每次都重新打开 Explanation 标签页。
- 在这一阶段，小屏幕上的面板不会变成模态窗口。只使用一种布局。

## 验收检查

1. 加载地图，不点击任何元素。面板就已经能够告诉用户这个仓库是什么——文件数量、被依赖最多的文件，以及应该从哪里开始阅读。而不是显示一个要求用户选择元素的空状态。
2. 选中一个文件：面板填充内容，浏览器的 Network 标签页记录到的新增请求数为零。将鼠标悬停在相邻节点上时，该节点会在地图上高亮，并且没有可感知的延迟，原因相同。
3. 面板中的导入数量和被依赖数量，必须与其下方列出的条目数量一致。如果显示七个，就必须列出七条文件路径。
4. 打开 Explanation 标签页，然后选中另一个文件。Explanation 标签页仍然保持打开状态。

## 本阶段不包含

影响范围（Blast Radius）和依赖链（Dependency Chain）按钮。
